# Project Instructions for AI Agents

These rules are mandatory for every change in this repository.

## Database — STRICT RULE: only two SQL files, ever

This project has exactly **two** SQL files and must always stay that way:

1. **`database.sql`** (project root) — the complete fresh-install file:
   schema (13 tables) + default content + default admin login.
   One import into the `wellness` database = fully working site.
2. **`storage/backups/wellness-*.sql`** — real database backups
   (generated by `app/scripts/backup.php` / Admin → Backup).
   Import one only when restoring the real data.

### Never do this

- ❌ **Never create new one-off SQL patch/migration files**
  (no `update-*.sql`, no `fix-*.sql`, no `migration-*.sql`).
- ❌ Never create a second "complete" dump alongside `database.sql`.
- ❌ Never import SQL into the real `wellness` database to "test" —
  use a throwaway database (e.g. `test_db_sql`), then drop it.

### When content or schema must change

1. Edit the default content in `app/data/*.php` (or the schema in
   `database.sql` and `app/scripts/seed.php` together — they must match).
2. Apply to a local database with `php app/scripts/seed.php`.
3. Refresh `database.sql` so it stays the single complete installer
   (re-export from phpMyAdmin, or run `php app/scripts/backup.php` and copy
   the dump to the project root as `database.sql`).
4. Schema changes for already-deployed databases are applied by editing
   `seed.php` (idempotent `CREATE TABLE IF NOT EXISTS` + idempotent
   `ALTER` guards) — **not** by adding a new SQL file.

### File purposes

| File | Purpose |
|---|---|
| `database.sql` | Fresh install — one import, site ready (content + admin login) |
| `storage/backups/wellness-*.sql` | Restore real data (admin users, bookings) |
| `app/scripts/seed.php` | Re-sync `app/data/*.php` content into an existing DB |
| `app/data/*.php` | Source of truth for default content |

Both SQL files describe the **same** `wellness` database.
Image/media paths stored in the DB are of the form
`/wellness/public/uploads/...` (the app runs in a `/wellness` subfolder).
